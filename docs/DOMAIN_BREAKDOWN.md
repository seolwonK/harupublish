# Domain Breakdown

## 전체 도메인 분리

Haru 백엔드는 사용자 역할, 레슨 프로필, 예약, 결제/정산, 알림, 운영 관리가 서로 강하게 연결된다. MVP에서는 아래 도메인 경계를 기준으로 시작하고, 구현 단계에서 도메인 간 직접 참조를 최소화한다.

| 도메인 | 핵심 책임 | 우선순위 |
| --- | --- | --- |
| Auth/User | 가입, 로그인, 토큰, 역할, 프로필 | P0 |
| Tutor Profile | 전문가 등록, 소개, 가격, 언어, 승인 상태 | P0 |
| Schedule | 가능 시간 등록, 시간대 변환 기준 | P0 |
| Booking | 예약, 변경, 취소, 입장 가능 여부, 완료 | P0 |
| Payment | 결제 요청/내역/상태, 수수료/할인 기준 | P1 |
| Settlement | 튜터 수익 반영, 인출 요청, 정산 상태 | P1 |
| Chat/Notification | 메시지, 예약 알림, 이메일 알림 | P2 |
| Review/Report | 리뷰, 이슈 신고, 후기 검수 | P2 |
| Admin | 승인, 운영 조회, 제재, 수동 처리 | P1 |
| Video Session | Jitsi 링크, 입장 정책, 녹화본 참조 | P1 |

## Auth/User

### 책임

- 이메일/소셜 로그인 기반 사용자 인증
- Access Token, Refresh Token, Logout, Me API 기준 관리
- 사용자 기본 프로필: 이름/닉네임, 이메일, 휴대전화, 표준 시간대, 계정 상태
- 역할 관리: Student, Tutor, Admin
- 현재 사용 중인 역할(activeRole) 관리

### 우선순위

P0. 모든 도메인이 사용자 식별과 권한 판단에 의존하므로 가장 먼저 구현한다.

### 현재 단계에서 구현하지 않는 것

- 실제 OAuth 제공자 연동 코드
- 비밀번호 재설정, 이메일 인증, 2FA 등 확장 기능

## Tutor Profile

### 책임

- 튜터가 자신의 레슨 페이지를 등록/수정
- 짧은 소개, About me, What I Offer, 소개 영상 또는 YouTube URL
- 가능한 언어 목록
- 과목: Korean language, Kpop, Kbeauty, other
- 25분/50분 수업 가격
- 초기 리뷰 최대 3개 등록 정책
- 지급 수단 등록 완료 후 관리자 승인 대기 상태로 전환

### 우선순위

P0. 예약과 결제는 승인된 튜터 프로필을 기반으로 해야 한다.

### 현재 단계에서 구현하지 않는 것

- 영상 업로드/녹화 구현
- 썸네일 생성 구현
- 언어 레벨 선택
- 튜터별 URL 공유 기능의 실제 라우팅 구현

## Schedule

### 책임

- 튜터가 가능한 시간을 30분 단위로 등록
- 오늘부터 1주치 표시, 좌우 이동으로 최대 5장까지 탐색하는 정책 반영
- 학생/튜터의 표준 시간대 기준으로 표시
- 저장 기준은 UTC, 표시 기준은 사용자 시간대

### 우선순위

P0. 예약 가능한 시간 산정의 기반이다.

### 현재 단계에서 구현하지 않는 것

- 서머타임 상세 검증 로직
- 반복 일정, 예외 일정, 캘린더 외부 연동

## Booking

### 책임

- 학생이 튜터, 수업 옵션, 시간대를 선택해 예약
- My Bookings의 월간 캘린더/목록 조회 기준 제공
- 수업 시작 10분 전부터 Join lesson 허용
- 수업 3시간 전까지 변경/취소 허용
- 변경/취소 사유 저장
- 회차권 구매 시 Lessons to Schedule 수량 관리
- 남은 레슨을 Balance로 전환하는 정책 후보 관리

### 우선순위

P0. Haru MVP의 핵심 거래 흐름이다.

### 현재 단계에서 구현하지 않는 것

- 복잡한 변경 요청 승인 절차. PPT는 학생/강사 모두 사유 입력 후 변경 가능한 간단한 정책을 선호한다.
- 취소율/변경율 공개

## Payment

### 책임

- 1회/5회/10회권 결제 후보
- 5회권 5%, 10회권 10% 할인 정책
- 학생 결제 수수료 5% 안내 및 계산
- 결제 수단 후보: 카드, PayPal, Google Pay, Apple Pay, KakaoPay
- 결제 상태: 요청, 성공, 실패, 취소, 환불 요청 등

### 우선순위

P1. 예약 MVP에 필요하지만, 초기 문서화 단계에서는 실제 PG 연동보다 결제 상태 모델과 금액 산정 기준을 먼저 정의한다.

### 현재 단계에서 구현하지 않는 것

- 계좌이체
- 실제 PG/MoR 연동
- Trial lesson 50% 정책

## Settlement

### 책임

- 튜터 수업료에서 플랫폼 수수료 15% 차감
- 수업 완료 후 일정 시간 경과 시 튜터 수익에 반영
- 학생 이슈 신고 시 지급 보류 상태 처리
- 월 1회 인출/정산 안내
- 인출 수단: 국내 계좌, PayPal, Payoneer
- 송금 수수료는 MVP 기준 3.5%로 통일하는 정책 후보

### 우선순위

P1. 실제 송금 자동화 전에도 운영자가 정산 상태를 확인할 수 있어야 한다.

### 현재 단계에서 구현하지 않는 것

- 실제 자동 송금
- 국가별/수단별 환전 수수료 최적화

## Chat/Notification

### 책임

- 학생-튜터 1:1 채팅방
- 예약, 변경, 취소, 30분 전 리마인더 알림
- 신규 채팅 및 알림 이메일 발송
- 채팅창에 상대방 시간대 표시

### 우선순위

P2. 예약과 운영 플로우 안정화 이후 적용한다.

### 현재 단계에서 구현하지 않는 것

- 휴대폰 푸시 알림
- 접속 상태 표시
- Read/Unread 표시

## Review/Report

### 책임

- 수업 완료 후 학생 리뷰 작성
- 튜터 초기 리뷰 최대 3개 직접 등록
- 문제 신고 사유 저장
- 관리자 후기 검수, 삭제, 비공개 처리

### 우선순위

P2. 신뢰 기능이지만 Auth, Tutor, Booking 이후에 붙인다.

### 현재 단계에서 구현하지 않는 것

- 자동 욕설/외부 링크 필터링
- 신고 증빙 스크린샷 업로드 구현

## Admin

### 책임

- 대시보드 운영 지표
- 회원 검색, 상태 변경, 정지/탈퇴 처리
- 전문가 승인/거절
- 예약/레슨 상태 조회
- 결제/정산/환불 요청 조회 및 수동 처리
- 신고/후기 검수
- 비매너 회원 block
- 수업 녹화본 접근

### 우선순위

P1. 튜터 승인과 결제/정산 운영 때문에 MVP 초기에 필요하다.

### 현재 단계에서 구현하지 않는 것

- 고급 통계/분석
- 공지/FAQ/프로모션/배너 관리
- 관리자 권한 세분화

## Video Session

### 책임

- Booking별 Jitsi Meet 링크 생성/저장 기준
- 수업 시작 10분 전 입장 가능 여부 판단
- 수업 녹화본 저장 위치 또는 참조 정보 관리
- 관리자 녹화본 조회 권한 기준

### 우선순위

P1. 예약 이후 실제 수업 진행을 위해 필요하다.
