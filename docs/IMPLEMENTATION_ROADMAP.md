# Implementation Roadmap

> Target spec / roadmap document. 현재 구현 완료 여부는 README와 API_PLANNING.md의 현재 구현 API 목록을 기준으로 확인한다.

## 개발 우선순위 원칙

Haru MVP는 인증된 사용자가 튜터 프로필을 보고 예약/결제/수업을 완료하는 흐름이 핵심이다. 따라서 사용자 식별과 권한 구조를 먼저 세우고, 그 위에 튜터 프로필, 스케줄, 예약, 결제/정산, 알림, 관리자 기능을 순서대로 올린다.

## 1단계: Auth/User

### 구현 목표

- 이메일 회원가입/로그인
- Access Token, Refresh Token, logout, me
- 사용자 기본 프로필
- Student/Tutor/Admin role 구조
- activeRole 기반 화면 모드 전환 기준
- 계정 상태: 활성, 정지, 탈퇴 후보
- 표준 시간대 저장

### 제외 범위

- 실제 소셜 로그인 provider 연동
- 비밀번호 재설정
- 이메일 인증
- 2FA

## 2단계: Tutor Profile

### 구현 목표

- 튜터 프로필 1인 1개 등록/수정/조회
- 짧은 소개, About me, What I Offer
- 가능한 언어, 과목, 가격, 25분/50분 옵션
- 소개 영상 또는 YouTube URL 저장 기준
- 지급 수단 등록 정보
- 등록 완료 후 관리자 승인 대기 상태
- 공개 튜터 목록과 상세 조회

### 제외 범위

- 영상 직접 녹화/업로드 구현
- 썸네일 처리
- 언어 레벨
- 추천/검색/고급 필터

## 3단계: Schedule/Booking

### 구현 목표

- 튜터 가능 시간 등록
- UTC 저장 및 사용자 시간대 표시 기준 적용
- 학생 예약 생성
- 1회/5회/10회권에 따른 Lessons to Schedule 관리 후보
- 예약 목록: 캘린더/목록 표시용 API
- 수업 시작 10분 전 Join 가능 여부
- 3시간 전까지 변경/취소
- 완료 수업 목록

### 제외 범위

- 외부 캘린더 연동
- 반복 일정 고도화
- 변경 요청 승인 플로우
- 취소율/참여율 공개

## 4단계: Payment/Settlement

### 구현 목표

- 결제 요청과 결제 상태 관리
- 1회/5회/10회권 금액 계산
- 5회 5%, 10회 10% 할인
- 학생 결제 수수료 5% 계산
- 튜터 플랫폼 수수료 15% 차감
- 수업 완료 후 튜터 수익 반영
- 이슈 신고 시 지급 보류
- 인출 신청과 정산 상태 관리
- 관리자 결제/정산 조회

### 제외 범위

- 실제 PG 연동
- 실제 자동 송금
- 계좌이체
- Trial lesson
- 국가별 환전/송금 수수료 차등 정책

## 5단계: Chat/Notification

### 구현 목표

- 학생-튜터 채팅방
- 메시지 저장/조회
- 예약 생성/변경/취소 알림
- 수업 30분 전 리마인더
- 이메일 알림 발송 기준
- 채팅창 내 상대방 시간대 표시

### 제외 범위

- 휴대폰 푸시 알림
- 접속 상태 표시
- Read/Unread 표시
- 고급 실시간 채팅 인프라 최적화

## 6단계: Admin

### 구현 목표

- 대시보드 요약
- 회원 검색/상태 변경
- 전문가 승인/거절
- 전체 예약/레슨 조회
- 결제/정산 조회와 환불 요청 관리
- 신고/후기 관리
- 관리자 녹화본 참조
- 비매너 회원 block

### 제외 범위

- 고급 통계/분석
- 카테고리별 세부 매출 분석
- 공지/FAQ/프로모션 관리
- 관리자 계정/권한 세분화

## 병렬 검토가 필요한 외부 연동

- 결제/MoR/PG 제공자 선정
- Jitsi Meet 링크 생성 및 녹화 저장 방식
- 이메일 발송 provider 선정
- 영상 업로드 또는 YouTube URL 방식 중 MVP 선택
- PayPal/Payoneer/국내 계좌 정산 운영 방식
